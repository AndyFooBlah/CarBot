# CarBot journal

Append-only. Every entry starts with a UTC timestamp and a tag: `[step]`, `[decision]`, `[friction]`, `[learning]`, `[surprise]`, `[incident]`, `[idea]`, `[milestone]`. Never edit or delete a past entry; to correct one, append a new entry naming the earlier entry's timestamp. The rule is in `~/.claude/CLAUDE.md` ("Project journal").

Entries before 2026-10-17 were backfilled from git history and session memory. Timestamps come from the commits they describe and are accurate to the minute; the reasoning attached to them was reconstructed afterwards, so treat the *why* as a summary rather than a contemporaneous note.

- 2026-04-12T04:28Z [step] Product requirements and technical design committed first, before any code.
- 2026-04-12T04:54Z [milestone] The whole application built in one sitting: React frontend, Cloud Functions, Firestore rules, tests. Firebase project `carbot-andybrook`.
- 2026-04-12T06:18Z [friction] The first evening went mostly on integration faults rather than features: storage rules path syntax, duplicate React and Firebase instances needing `resolve.dedupe`, incomplete composite indexes, an `@eslint/js` major mismatch breaking CI.
- 2026-04-12T07:13Z [decision] The structured per-day schedule editor was replaced with Gemini-powered freeform input. Typing "school run 8am weekdays, swimming Tuesdays" beats filling a grid, and the model only has to produce a schedule object the app validates.
- 2026-04-12T07:30Z [decision] Fixed location fields replaced with a named location list plus Maps geocoding, so the bot can reason about "grandma's house" rather than coordinates.
- 2026-04-12T18:11Z [friction] Live use surfaced a system-instruction bug and Firestore permission errors that no test had caught — the pattern for this project all year: faults appear in the car, not in CI.
- 2026-04-12T18:21Z [step] Bot name setting with a first-session self-introduction; the bot takes the first turn with a trip observation and deliberate variability, so it does not greet identically every drive.
- 2026-04-14T05:41Z [decision] Knowledge tools migrated out of VoiceCommon into KnowledgeCommon, and CarBot consumes both. Keeps the voice-session layer usable without the Wikipedia/maps/weather surface. See [[voicecommon]] and [[knowledgecommon]].
- 2026-04-18T04:21Z [decision] Per-user Gemini Live voice quota plus a four-hour hard session timeout. A voice session left open is a bill, not just a bug. A `/diagnostics` page with service probes, quota and session triggers landed the same evening.
- 2026-04-18T05:00Z [step] Security pass: recipient email masked in the session-summary send log, input validation on `geoProxy`, explicit deny on the `_usage` collection.
- 2026-04-18T20:16Z [milestone] Larger security pass (H1/H2/M1, then M2/M3/M5, then M6): `wikipedia_cache` writes locked to the server, server-filler callable, `geoProxy` rate limits with model-interpretable errors, `onSessionCompleted` duration gate, transcript length cap, context upload allowlist, cache TTL cleanup.
- 2026-04-28T03:18Z [milestone] The broker architecture. A server-side Gemini broker was ported in, the client key removed from CarBot's own code, `VITE_GEMINI_API_KEY` dropped from the bundle entirely, and hard guards added that fail the build if anything secret-shaped reaches client output. The rule was then written into the repo's CLAUDE.md.
- 2026-04-28T03:48Z [learning] The reason this was non-negotiable rather than a nice-to-have: a key embedded in a compiled bundle had previously been scraped, abused to run up a large bill, and got the owner's GCP project suspended. `VITE_*` and friends are *intentionally* public and should be treated as red flags for anything secret-shaped.
- 2026-05-31T21:45Z [decision] Owner reviewed and accepted the shared `wikipedia_cache` side channel during the security audit: any signed-in user can learn that *someone* in the project looked up article X. Accepted in exchange for cache efficiency and avoiding redundant embedding cost. Not to be re-filed as a finding in future audits; revisit only if cache metadata gets richer or the app goes multi-tenant.
- 2026-05-09T20:03Z [step] VoiceSimulator integrated for conversational testing; predeploy hooks added so a deploy cannot ship a stale build; the liveToken broker pinned to the `v1alpha` `authTokens.create` endpoint.
- 2026-05-09T23:05Z [step] Math-game tools, `reconcileMemories`, a real Home landing page, and the bot actually finalizing a session when it calls `endSession`.
- 2026-07-18T21:30Z [step] Email ingestion with a DMARC gate and masked logging; sessions rules field allowlist. Pre-publication docs: LICENSE, SECURITY.md, stale gap retired, README facts corrected.
- 2026-09-11T05:03Z [milestone] voice-common and knowledge-common consumed from npm instead of sibling checkouts; CI down to a single checkout.
- 2026-09-11T05:05Z [incident] `gemini-3.1-flash-lite-preview` had been shut down upstream and was still referenced; replaced, model IDs centralized, and a `probeModels` diagnostic added. Removed models return 404 with no warning, so a project needs a way to ask which ids still answer.
- 2026-09-11T05:15Z [step] Safety: a non-negotiable SAFETY block in the instruction, untrusted-data delimiting, explicit `safetySettings`, email docs inactive by default.
- 2026-09-11T05:33Z [step] Data lifecycle: session delete, account deletion, audio retention, privacy statement.
- 2026-09-19T18:36Z [step] Live sessions moved to `gemini-3.8-live` (stable, same price).
- 2026-10-17T04:46Z [learning] Two standing traps here. CarBot has **two** Live paths — `useCarbotSession.ts` through voice-common, and `src/services/voicePreview.ts` which calls `ai.live.connect` directly for the settings voice audition — and the second is easy to miss on a model migration. And the tests mock the voice-common module wholesale, so they would not catch a Live config regression at all; weatherbot-app's `evals/` is the only real Live coverage in the family.
